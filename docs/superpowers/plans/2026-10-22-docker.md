# Docker for the app — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `docker compose up` runs MongoDB + backend + frontend with the same Python / PyTorch / package versions on every teammate's PC.

**Architecture:** Three services in `docker-compose.yml`. The images hold only the environment (Python 3.13 + PyTorch cu126 + pinned packages; Node 24 + npm packages); the repository is mounted, so code, `data/`, `models/` and `backend/.env` come from the PC. Ollama stays on the PC (`host.docker.internal:11434`).

**Tech Stack:** Docker Compose, `python:3.13-slim`, PyTorch cu126 wheels, `node:24-slim`, `mongo:7.0`, PowerShell 5.1 (setup script).

Spec: `docs/superpowers/specs/2026-10-22-docker-design.md`.

## Global Constraints

- No application code changes (the backend reads `MONGO_URL` / `OLLAMA_URL`, the frontend proxy reads `DRESSME_API`).
- Nothing under `data/`, `models/`, `backend/.env` is ever copied into an image or committed.
- `scikit-learn==1.6.1` (the version `colour_model.joblib` was saved with).
- pymongo stays `<4.14` (backend/requirements.txt), MongoDB image `mongo:7.0`.
- The non-Docker setup keeps working; the README gets a new section, not a replacement.
- `docker/setup.ps1` must run on Windows PowerShell 5.1 and never overwrite an existing `backend/.env`.
- These are infrastructure files: each task's "test" is a command with an expected output.

- [ ] **Step 3: Write `docker/backend.Dockerfile`**

```dockerfile
# The backend's environment: Python 3.13 + PyTorch (GPU build, CUDA 12.6) + the exact
# package versions of docker/constraints.txt. The code, data and models are NOT copied
# in: docker-compose.yml mounts the repository at /app.
FROM python:3.13-slim

# OpenCV (used by rembg for background removal) needs these system libraries
RUN apt-get update && apt-get install -y --no-install-recommends libglib2.0-0 libgl1 \
    && rm -rf /var/lib/apt/lists/*

ENV PYTHONUNBUFFERED=1 PYTHONDONTWRITEBYTECODE=1 PIP_DISABLE_PIP_VERSION_CHECK=1

WORKDIR /tmp/requirements
COPY requirements.txt requirements-models.txt docker/constraints.txt ./
COPY backend/requirements.txt backend-requirements.txt
# PyTorch first, from its GPU index (as in the README); the cache mount keeps the
# 2.6 GB download between rebuilds
RUN --mount=type=cache,target=/root/.cache/pip \
    pip install torch torchvision --index-url https://download.pytorch.org/whl/cu126 -c constraints.txt
RUN --mount=type=cache,target=/root/.cache/pip \
    pip install -r requirements.txt -r requirements-models.txt -r backend-requirements.txt -c constraints.txt

WORKDIR /app/backend
CMD ["uvicorn", "app.main:create_app", "--factory", "--host", "0.0.0.0", "--port", "8000"]
```

- [ ] **Step 4: Build it**

Run: `docker build -f docker/backend.Dockerfile -t dressme-backend .`
Expected: ends with `naming to docker.io/library/dressme-backend`.

- [ ] **Step 5: Check the GPU and the colour model in the image**

Run (bash): `docker run --rm --gpus all -v "$PWD:/app" dressme-backend python -W error::UserWarning -c "import torch, joblib, sklearn; print(torch.__version__, torch.cuda.is_available(), sklearn.__version__); joblib.load('/app/models/checkpoints/colour_model.joblib'); print('colour model OK')"`
Expected: `2.14.1+cu126 True 1.6.1` then `colour model OK` (no `InconsistentVersionWarning`).

- [ ] **Step 6: Freeze the exact versions and rebuild with them**

Run (bash): `docker run --rm dressme-backend pip freeze > docker/constraints.txt` then put a two-line comment on top (`# Exact package versions of the backend image (pip freeze of a working build).` / `# scikit-learn==1.6.1: models/checkpoints/colour_model.joblib was saved with it.`), then `docker build -f docker/backend.Dockerfile -t dressme-backend .`
Expected: build succeeds; `pip install` steps report nothing new to download beyond the cached wheels.

### Task 2: Compose with MongoDB and the backend

**Files:**
- Create: `docker-compose.yml` (services `mongo`, `backend`; volumes `mongo-data`, `model-cache`)

**Interfaces:**
- Consumes: `docker/backend.Dockerfile` (Task 1).
- Produces: services `mongo` (port 27017) and `backend` (port 8000, hostname `backend` inside the network) used by Task 3.

- [ ] **Step 1: Free port 27017** — the earlier standalone container `dressme-mongo` (empty, made during setup) must go: `docker rm -f dressme-mongo; docker volume rm dressme-mongo-data` after checking it holds no database other than `admin`, `config`, `local`.

- [ ] **Step 2: Write `docker-compose.yml` (mongo + backend part)**

```yaml
# DressMe with one command: MongoDB + backend + frontend (README "Run with Docker").
# The images hold the environment only; this folder is mounted, so code, data/, models/
# and backend/.env come from your PC. Ollama (the chat model) runs on your PC, not here.
# No NVIDIA GPU? docker compose -f docker-compose.yml -f docker-compose.cpu.yml up
name: dressme

services:
  mongo:
    image: mongo:7.0
    ports: ["27017:27017"]
    volumes: [mongo-data:/data/db]

  backend:
    build: {context: ., dockerfile: docker/backend.Dockerfile}
    volumes:
      - .:/app
      - model-cache:/cache          # FashionCLIP + rembg downloads, kept across rebuilds
    environment:
      # these win over backend/.env, so the same .env works with and without Docker
      MONGO_URL: mongodb://mongo:27017
      OLLAMA_URL: http://host.docker.internal:11434
      HF_HOME: /cache/huggingface
      U2NET_HOME: /cache/u2net
    extra_hosts: ["host.docker.internal:host-gateway"]
    ports: ["8000:8000"]
    depends_on: [mongo]
    deploy:
      resources:
        reservations:
          devices: [{driver: nvidia, count: all, capabilities: [gpu]}]

volumes:
  mongo-data:
  model-cache:
```

- [ ] **Step 3: Start and check health**

Run: `docker compose up -d --build mongo backend`, wait for `Application startup complete` in `docker compose logs backend`, then `curl -s localhost:8000/health`.
Expected: `{"status":"ok"}`.

- [ ] **Step 4: Run the backend tests in the container**

Run: `docker compose exec backend python -m pytest -q`
Expected: all pass (~305; `test_jobs.py::test_run_to_the_end_with_log_and_progress` is known to be timing-sensitive in a full run: re-run it alone if it is the only failure).

- [ ] **Step 5: Check Ollama through host.docker.internal**

Run: `docker compose exec backend python -c "import httpx; print([m['name'] for m in httpx.get('http://host.docker.internal:11434/api/tags').json()['models']])"`
Expected: a list containing `dressme-chat-v4:latest`.

- [ ] **Step 6: Commit**

```bash
git add docker-compose.yml
git commit -m "Docker: compose with MongoDB and the backend (GPU, Ollama on the PC)"
```

### Task 3: Frontend service

**Files:**
- Create: `docker/frontend.Dockerfile`
- Modify: `docker-compose.yml` (add `frontend` service)

**Interfaces:**
- Consumes: service `backend` on port 8000 (Task 2).

- [ ] **Step 1: Write `docker/frontend.Dockerfile`**

```dockerfile
# The frontend's environment: Node 24 + the npm packages of frontend/package-lock.json.
# They are installed in /app/node_modules, one folder above the mounted frontend/, so
# the PC's own frontend/node_modules (built for Windows) is never used here: Node looks
# for packages in the parent folders too.
FROM node:24-slim
WORKDIR /app
COPY frontend/package.json frontend/package-lock.json ./
RUN --mount=type=cache,target=/root/.npm npm ci --no-audit --no-fund
WORKDIR /app/frontend
CMD ["/app/node_modules/.bin/vite", "--host", "0.0.0.0"]
```

- [ ] **Step 2: Add the service to `docker-compose.yml`** (after `backend`)

```yaml
  frontend:
    build: {context: ., dockerfile: docker/frontend.Dockerfile}
    volumes:
      - ./frontend:/app/frontend
      - /app/frontend/node_modules  # hides the PC's Windows node_modules (empty here)
    environment:
      DRESSME_API: http://backend:8000   # the dev server forwards /api/... there
    ports: ["5173:5173"]
    depends_on: [backend]
```

- [ ] **Step 3: Check the page and the proxy**

Run: `docker compose up -d --build frontend`, then `curl -s localhost:5173/ | grep -c '<div id="root">'` and `curl -s localhost:5173/api/health`.
Expected: `1` and `{"status":"ok"}`.

- [ ] **Step 4: Check that edits reload** — touch `frontend/src/main.tsx` (add then remove a blank line) and look for `hmr update` / `page reload` in `docker compose logs frontend`. If nothing appears, add `CHOKIDAR_USEPOLLING: "true"` to the service's environment and re-check.

### Task 5: One-time setup script

**Files:**
- Create: `docker/setup.ps1`

- [ ] **Step 1: Write it** (full content in the file; behaviour:)
  1. Stops with a clear message if Docker is not running (`docker info` fails).
  2. Creates `backend/.env` from `backend/.env.example` only if missing: random 64-char URL-safe `JWT_SECRET` (.NET RNG, no Python), `CHAT_ENGINE=ollama`, `OLLAMA_MODEL=dressme-chat-v4`; written as UTF-8 without BOM.
  3. If Ollama is installed and `dressme-chat-v4` is not in `ollama list`: rewrites the `FROM` line of `models/llm/dressme-chat-v4/Modelfile` to `FROM ./gguf/<the .gguf file>` and runs `ollama create dressme-chat-v4 -f Modelfile` in that folder. Warns (does not stop) when Ollama, the Modelfile or the GGUF is missing.
  4. Prints each needed file as `ok` / `MISSING` (required: classifier_best.pt, colour_model.joblib, dressme.csv, fashionclip.npy, fashionclip_ids.csv; optional: H&M files, shop snapshot, the two image folders).
  5. Ends with the next commands (`docker compose up --build`, `seed_demo`).

- [ ] **Step 2: Run it on this PC**

Run: `powershell -ExecutionPolicy Bypass -File docker\setup.ps1`
Expected: `backend\.env already exists: kept as it is`, `dressme-chat-v4 already registered`, the five required files `ok`, the image folders `MISSING (optional)`.

- [ ] **Step 3: Run it on a fresh copy** — in a scratch folder with only `backend/.env.example` and the script, check it creates `.env` with a 64-char `JWT_SECRET` and no BOM, and reports the required files as `MISSING`.

- [ ] **Step 4: Commit**

